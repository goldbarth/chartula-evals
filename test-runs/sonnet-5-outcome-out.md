### What's New

- **Generate and preview commands:** Two commands, `chartula preview` and `chartula generate`, take a `--tag` and `--repo` option and run the full changelog process. `preview` runs the same process as `generate` but writes and publishes nothing, so you can check the result first; an unknown command or a missing option now prints a clear message instead of crashing.
- **Automatic categorization:** Each change in the changelog is now placed into a category, such as feature, fix, or documentation, based on standard conventions in its title, rather than being decided by AI.
- **Three audience versions:** Every release now produces separate technical, customer, and product-manager versions of the changelog from the same source facts, so the three can never disagree; the customer version leaves out any change that isn't visible to users.
- **Rephrasing only:** Generated text is limited to rephrasing the established facts about a change; it does not invent details, numbers, or names, and stays brief when the source facts are thin.
- **Consistent formatting:** Every generated section now reads with the same bullet style and voice, no matter how the original pull requests were written; headings and other non-bullet text are left as they are.
- **Changelog.json now holds all text:** The `changelog.json` file written for a release now also stores the customer-facing and product-manager text alongside the technical facts, instead of separate marketing files being written.
- **CHANGELOG.md updates:** Each release now adds its own new section at the top of `CHANGELOG.md`, keeping earlier releases intact underneath. Re-running the same release replaces its own section in place instead of duplicating or reordering it.
- **GitHub release notes updated automatically:** Running `generate` now writes the generated text directly into the release's notes on GitHub; re-running the same release updates those notes rather than creating a second release.
- **Free accuracy check, always on:** A check now catches obvious mistakes in the generated text, such as numbers, quoted names, or breaking-change claims that don't appear in the source facts. It runs on every release at no extra cost and cannot be turned off.
- **Deeper accuracy check:** A second, AI-based check now reviews generated text against the source facts to catch subtle wording that changes the meaning of a change. It runs by default and can be turned off in the `faithfulness` section of your configuration.
- **Run metrics summary:** Every `preview` and `generate` run now ends with a summary of how many checks ran, how many issues they found, and how many tokens were spent, including whether the deeper check caught anything the free check missed. Use it to decide whether the deeper check is worth its cost for your releases.
- **Optional review before publishing:** A review mode lets you look at flagged passages and approve or edit the generated text before it's used. It is off by default; turn it on in the `review` section of your configuration.
- **Category display settings:** You can now set the order and display names of categories, and whether breaking changes are shown prominently, in the `categories` section of your `chartula.yaml`. Breaking changes are shown prominently by default, and an unrecognized category name in this section now causes a clear error at startup.
- **Label-based rules:** A label on a pull request can now exclude it from the changelog, force it into a specific category, or (in "only labeled" mode) be required before the pull request is included at all. These rules are optional and set in the `labels` section of your configuration; without any labels, the tool behaves as before.
- **Internal changes hidden by default:** Internal and chore-type changes are now left out of the changelog by default, even without any label rules. You can change which categories are excluded in the `filter` section of your configuration; breaking changes are never excluded this way.
- **Adjustable level of detail:** How much detail feeds into each change — title only, title and description (the default), or title, description, and linked issues — can now be set in the `factBase` section of your configuration.
- **Configuration file:** A `chartula.yaml` (or `.yml`) file at the root of your repository now lets you customize the tool's behavior; without one, or with settings left out, the tool runs on its built-in defaults. Copy the included `chartula.example.yaml` and uncomment what you need; a mistake in the file now shows a clear `Configuration error: ...` message instead of crashing, and environment variables still override anything set in the file.

### Bug Fixes

- Generated changelog text no longer gets cut off mid-sentence. Previously a run could truncate the text after about 1,024 tokens because no output limit was set; the limit is now always specified, defaults to a much higher value, and can be adjusted under the `llm` section of your configuration.
- Changes whose title or description merely discusses a breaking change are no longer marked as breaking themselves. Only an actual breaking-change declaration in the standard format is flagged, so unrelated mentions of the phrase no longer show up incorrectly in the changelog.
