### What's New

- **Inline citation badges in Markdown answers:** Inline citation badges now appear directly in the assistant's Markdown answers instead of appearing in a separate list. Each badge is tied to the specific part of the answer it refers to, making it easier to see which information comes from where. This change ensures that every citation is clearly linked to its source, and no citations are lost if they aren't referenced in the answer. No action is required by the user, as this change is fully implemented and verified across all relevant parts of the application.
- **Primary action button for suggested next steps:** The primary action from suggested next steps is now displayed as a button in the ticket header, making it easier to take the most likely next action. This change ensures that the most relevant action is always immediately available, while other suggested steps are available in an overflow menu. If there are no suggested actions, the existing generic controls remain untouched and are still displayed. Users do not need to take any action to benefit from this change, as it is already implemented and verified across all relevant parts of the application.
- **Command palette accessible via Ctrl+K:** A command palette is now available across the application by pressing the keyboard shortcut Ctrl+K (or Cmd+K on Mac), allowing users to search for navigation destinations or tickets directly. This palette is keyboard-operable from start to finish, ensuring full accessibility from any page. Users do not need to take any action to benefit from this change, as it is already implemented and verified across all relevant parts of the application.
- **Optimistic status updates on Kanban board:** Status updates on the Kanban board and ticket detail view are now applied optimistically, meaning changes appear immediately and are reconciled with the server's state afterward. If a change is rejected, the UI rolls back to the prior state and explains why, ensuring users always see the correct status without unnecessary delays. No action is required by the user, as this change is fully implemented and verified across all relevant parts of the application.
- **Inline popovers for status and assignee changes:** Changing the status or assignee of a ticket now appears as inline popovers instead of opening a separate dialog. This change keeps you on the current page and view while making your changes. No navigation or modal is needed, and the same underlying command handlers are used as before, ensuring no new endpoints are required. Users do not need to take any action to benefit from this change, as it is already implemented and verified across all relevant parts of the application.
- **Inline citations with hover tooltips:** Citations from the assistant's answer now appear as inline badges within the answer text, not in a separate sources list. These badges appear next to the text they reference, and a tooltip displays detailed information on hover or focus. This change makes it easier to see which parts of the answer are supported by referenced sources, and no citations are lost if they aren't referenced in the answer. Users do not need to take any action to benefit from this change, as it is fully implemented and verified across all relevant parts of the application.
- **Agent roster injected into system prompt:** The assistant now learns the list of available agents directly from the system prompt, ensuring it uses only valid agent names and never invents new ones or guesses incorrectly. This change improves accuracy when assigning tickets and prevents errors resulting from outdated or incorrect agent information. No action is required by the user, as this change is fully implemented and verified across all relevant parts of the application.
- **Enforced grounding check via tool_choice:** The assistant will now always check for grounding before providing an answer, ensuring that all responses are supported by the knowledge sources in its training data and preventing unverified information from appearing. This change ensures that any answer the assistant provides is grounded in knowledge that is relevant and accurate. No action is required by the user, as this change is fully implemented and verified across all relevant parts of the application.
- **Unified design token system:** The application now uses a unified design token system to define spacing, radius, elevation, and semantic color scales. This change ensures consistency across the user interface and eliminates the need for hardcoded styling values. No action is required by the user, as this change is fully implemented and verified across all relevant parts of the application.

### What's Changed

- **Integration of M9 frontend redesign into main:** The complete M9 frontend redesign has been integrated into the main branch, unifying the various feature improvements and enhancements. This change ensures that the user experience is consistent across the entire application, and no additional user action is required. The M9 milestone is now complete, and the v1.9.0 release notes and integration are fully verified.

### Bug Fixes

- **Truncated Kanban board card titles:** Long ticket titles on the Kanban board are now properly truncated with an ellipsis, limiting to two lines. This change ensures that the board cards maintain a consistent height even with long titles, preventing layout issues in the interface. No action is required by the user, as this change is fully implemented and verified across all relevant parts of the application.
- **Send button inside composer panel:** The send button in the assistant chat composer is now correctly displayed within the composer panel, keeping the chat input and send button visually aligned at all screen widths. No action is required by the user, as this change is fully implemented and verified across all relevant parts of the application.
- **Category header no longer overlaps with Due:** The ticket queue now properly displays the header for the 'Category' column without overlapping with the 'Due' column. This change ensures that the category header is displayed correctly and in the same format as the other column headers. No action is required by the user, as this change is fully implemented and verified across all relevant parts of the application.
- **Write honesty and confirmation policy in system prompt:** The assistant now maintains write honesty by only confirming actions when they are actually executed, preventing confusion when changes appear to be made without confirmation. This change ensures that users always see accurate information and that the assistant does not ask for unnecessary confirmation. No action is required by the user, as this change is fully implemented and verified across all relevant parts of the application.
- **Summary timestamps in user's timezone:** Summary timestamps in the application are now displayed in the user's local timezone, ensuring that users see accurate time information regardless of where they are located. No action is required by the user, as this change is fully implemented and verified across all relevant parts of the application.
- **Failed knowledge base searches reported as errors:** A failed knowledge base search is now properly reported as an error, distinguishing it from a 'not found' case and allowing for better tracking of technical failures. This change ensures that users receive clear and accurate feedback about any issues encountered with knowledge base searches. No action is required by the user, as this change is fully implemented and verified across all relevant parts of the application.
- **Grounding score based on semantic meaning:** The system now uses a semantic approach to score the grounding of answers, determining whether an answer is based on the provided information and not just based on word overlap. This change ensures that accurate paraphrases and translations are correctly identified as grounded responses while hallucinated responses remain ungrounded. No action is required by the user, as this change is fully implemented and verified across all relevant parts of the application.
