### What's New

- **Inline citation badges in Markdown answer:** Inline citation badges are now anchored directly in the assistant's Markdown answer. Every change is kept, so you no longer have to worry about losing edits if the connection drops. The badge includes a tooltip with the source title, heading, and snippet. Citations are numbered so they match the entries in the sources list. If a citation's title doesn't appear in the answer, it still stays in the sources list without being lost. Verification includes 9 unit tests and real-browser E2E checks against Postgres + pgvector + Voyage.
- **Primary action button for suggested steps:** The most likely next step in a ticket is now a primary button rather than a grey caption. The action runs immediately when clicked, so you no longer have to manually select the step. Unmapped steps still show as non-clickable text, and the existing generic controls remain available as fallback options. A ticket with no suggested steps falls back to the generic controls without showing an empty button. Verification includes full build and real-browser E2E checks.
- **Command palette accessible via Ctrl/Cmd+K:** A command palette is now available on every page via the `Ctrl/Cmd+K` shortcut. You can search for navigation targets and tickets directly from the palette, which appears over the current page. The search is debounced, so only the latest query is processed. The palette can be fully operated by keyboard, and focus is returned to the previous location when it's closed. No changes to the search endpoint or any external tool are required.
- **Optimistic status updates on the board:** Status changes on the Kanban board now render immediately with an optimistic update, and reconcile with the server afterward. If a move is rejected, it rolls back to the exact previous state. Errors display an informative code in a snackbar, so you no longer have to guess the reason for a failed change. No changes to ticket creation are involved.
- **Inline status and assignee edit popovers:** You can now change the ticket status or assign an agent using inline popovers rather than dialog boxes. The change is applied immediately without navigating away from the current tab. No new endpoints are added, and the existing command handlers are used, so you don't need to worry about new server-side logic. The dialog components are removed, and no new UI files are created.
- **Inline citation badges with hover preview:** Citations from the assistant are now anchored inline in the answer text, with a tooltip showing the source title, heading, and snippet. This makes the source clearly visible at the point where it's referenced. If the model didn't anchor a citation inline, a numbered sources list remains available as a fallback. An answer with no citations remains unchanged. This change is limited to the frontend without altering the assistant or tools.
- **Agent roster injected into system prompt:** Agent names are now injected into the system prompt so the assistant can accurately list assigned agents without guessing or inventing names. The model's answer includes only the valid agents present in the roster and avoids making up names that are not listed. This change ensures the assistant always lists the correct agents based on the current roster, not by error or trial.
- **Grounding check via tool choice:** The assistant now enforces a grounding check via the tool choice, ensuring that every answer is verified as correct before being rendered. This is done after any retrieval, and the model must confirm the answer's correctness before it’s displayed. This change provides additional safety and prevents answers that are not based on verified sources from being shown.
- **Design tokens for visual consistency:** A unified design token system now controls spacing, radius, elevation, and semantic colors across the application. This system replaces all hard-coded color literals, spacing, and radius values, ensuring a consistent look and feel. The use of tokens reduces the potential for visual drift and provides a single source of truth for design elements. No changes to functionality are required, only a shift in how design is expressed.

### What's Changed

- **M9 frontend redesign integrated into main:** The complete M9 frontend redesign has been merged into the main branch and is now included as part of v1.9.0. This includes all previous redesign features and release notes. This integration ensures that the release can be built and deployed from a single, unified source without any conflicts or discrepancies.

### Bug Fixes

- **Board card title wrapping for line-clamp:** The board card title is now properly wrapped to ensure that the -webkit-line-clamp is applied correctly. This prevents the title from overflowing the card and keeps the layout consistent within the lane. A long title is limited to two lines with an ellipsis, ensuring that the card height remains consistent for all tickets.
- **Assistant send button inside panel:** The send button for the assistant composer is now positioned correctly within the panel, ensuring it doesn't overflow the panel's boundaries. The send button is now located within the panel’s padding area rather than extending beyond the panel. This ensures that all elements are aligned correctly even at smaller screen sizes.
- **Category header alignment with Due column:** The `Category` header now aligns correctly with the `Due` column in the ticket queue, so they no longer overlap. The category header has a fixed width, and it is now displayed as uppercase for consistency with other headers. This ensures that all headers are aligned properly and that the layout is visually correct in all themes.
- **Write honesty and confirmation policy:** The assistant agent now includes new instructions in the system prompt to ensure write honesty and limit confirmation to only when necessary. The assistant will now only assert a change after the corresponding tool call is successfully executed. It also avoids asking the user for a confirmation when a change has already been requested, ensuring that the assistant doesn’t repeat questions unnecessarily.
- **Summary timestamps in user’s local timezone:** Summary timestamps now display in the user’s local time zone, consistent with how the ticket detail view is shown. This change ensures that all time-sensitive information displayed in the summary matches what’s shown elsewhere in the application. This is based on the user’s set timezone, and a test case has been added to ensure that this behavior is maintained consistently.
- **Failed knowledge base search reported as error:** Technical failures in knowledge base searches are now reported as errors, distinguishing them from cases where knowledge base access is unavailable. This change allows the dashboard to accurately reflect the tool’s error rate by distinguishing between actual failures and unavailable access. A unit test has been added to ensure that this distinction is correctly applied.
- **Grounding scored by meaning rather than word overlap:** Grounding is now scored based on meaning rather than just word overlap, ensuring that answers that are paraphrased or translated correctly are still marked as grounded. This change eliminates incorrect labeling of correctly paraphrased answers as ungrounded. This is now implemented using semantic similarity, and a fallback lexical method is used when embedding is not available.
