# Comparison runs, October 2026: plan and how it ran

Status: complete. All 84 runs were made on 2026-10-09: 72 in the main matrix and 12 in the optional block.
Results: [`cmp-2026-10-stats/report.md`](cmp-2026-10-stats/report.md).
The Chartula documentation cites [`results/october/runs.csv`](results/october/runs.csv) and [`results/october/configurations.csv`](results/october/configurations.csv), the same runs in another layout.
Chartula: `0.1.0-preview.5+541842d`, the installed binary.

## What this collects

Cost, duration, technical behaviour and the checkers' reports, for three configurations per provider on four real releases.
It keeps the complete material of every run, so the texts can be judged later and separately.
It makes no quality ranking: no human review and no LLM judge is part of it.

## Configurations

Each provider runs the same three, named by who renders and who checks:

| Configuration | Renders | Checks |
| --- | --- | --- |
| `g-g` | cheap | cheap |
| `g-m` | cheap | middle |
| `m-m` | middle | middle |
| `p-m` (optional) | premium | middle |

Every run renders `technical` and `customer`, with `factBase.depth: title-and-description` and the thorough check on, and publishes nothing (`--no-publish`).

## Models and thinking

Each model runs at the lowest thinking setting it accepts, set explicitly for rendering and for the check.
The settings therefore differ between models, and every table names them.

| Tier | Model | Thinking | $ in / cached / out per 1M | Why this setting |
| --- | --- | --- | --- | --- |
| OpenAI cheap | `gpt-6-luna` | `disabled` | 0.10 / 0.01 / 0.50 | `none` is supported. |
| OpenAI middle | `gpt-6.1-sol` | `low` | 2.00 / 0.10 / 10.00 | `none` and `minimal` are not supported. |
| OpenAI premium | `gpt-6-astra` | `low` | 10.00 / 1.00 / 50.00 | The model page lists `low` as the lowest. |
| Anthropic cheap | `claude-haiku-5-5` | `disabled` | 0.10 / 0.01 / 0.50 | `disabled` is accepted at effort `high` or below. |
| Anthropic middle | `claude-sonnet-5-5` | `low` | 2.00 / 0.10 / 10.00 | `disabled` returns a 400. |
| Anthropic premium | `claude-opus-5-5` | `low` | 4.00 / 0.20 / 20.00 | `disabled` returns a 400 at every effort. |

Sources, read on 2026-10-09: the OpenAI pricing page and the three model pages, the Anthropic pricing page and model reference.
The figures are in `prices-2026-10-09.json`, confirmed by Felix against both pricing pages on 2026-10-09.

What is not yet shown by a run:

- `gpt-6-luna` is the cheap model as planned. The pricing page lists no `gpt-6.1-luna`.
- `claude-haiku-5-5`, `claude-opus-5-5` and `gpt-6-astra` have not been run with Chartula. Nothing in the reference speaks against them; the pilot is the proof.
- `claude-sonnet-5-5` has run with Chartula at `provider-default` only, `gpt-6.1-sol` at `low`.
- `claude-haiku-5-5` counts the same text as about 30% more tokens, and a request over 100,000 prompt tokens pays five times the price. The largest call here is estimated at 29,000 tokens.
- Chartula 0.1.0-preview.5 refuses `disabled` before a run only for Claude Fable. For `claude-sonnet-5-5` and `claude-opus-5-5` the API refuses it on the first call instead.

## Same conditions

- One binary and one release range per case for every configuration.
- `sweep.py --baseline` runs `chartula preview` before anything is spent and keeps the facts it lists, the release's size, the clone's commit and its `chartula.yaml` in `sweeps/<plan>/_baseline/`.
- A sweep refuses to start when the clone or its configuration has changed since the baseline.
- A run is marked `mismatch` when its record counts another release than the baseline, when its facts differ from the plan's first finished run, or when its record names another model or setting than the cell.
- A run in which every model call was answered and Chartula still refused an audience's text is `incomplete`. It is a finished draw and is not repeated, so every cell has three draws and the report says in how many an audience did not render. Only a run whose calls failed, or that left no record, is `failed` and tried again.
- The clones: `~/repos/chartula-sweep-cmp` (detached at `v0.1.0-preview.5`, its `chartula.yaml` is the same at both tags), `~/repos/ServiceDeskLite-sweep`, `~/repos/Ingestor-sweep` (neither has a `chartula.yaml`).
- `small` and `large` share a clone, so never run two sweeps at once.

## Size

3 configurations x 4 cases x 3 repetitions: 36 `generate` runs per provider, 72 in all.
The optional block adds 6 per provider.

The budget is 5.50 per provider, with 1.50 kept back from about 7.
What the estimate rests on, and where it can be wrong:

- 4.3 characters per token, as measured on `typical` for `gpt-6-sol` and `claude-sonnet-5-5`; 30% more tokens for `claude-haiku-5-5`.
- The check reads about as much as the rendering, as measured.
- Output per rendered fact is measured for `gpt-6-sol` at `low` and for `claude-sonnet-5-5` at `provider-default`, and assumed for every other model and setting.

Checked against a measurement: `typical` `m-m` is estimated at 0.12 for OpenAI, and `gpt-6-sol` at `low` cost 0.105 on 2026-09-25.

## Stages

A pilot is the first repetition of a plan, not a run beside it.
After every stage, read the spend before starting the next.

| Stage | What | Estimated, OpenAI / Anthropic |
| --- | --- | --- |
| 0 | Baseline of all four plans. No tokens, about 103 GitHub requests, so it needs `GITHUB_TOKEN`. Done on 2026-10-09. | 0 |
| 1 | `difficult`, repetition 1. Every model and setting runs once at the lowest price. | 0.03 / 0.05 |
| 2 | `small` and `typical`, repetition 1. | 0.28 / 0.39 |
| 3 | `large`, repetition 1. | 0.35 / 0.49 |
| 4 | `difficult`, `small`, `typical`, repetitions 2 and 3. | 0.61 / 0.89 |
| 5 | `large`, repetitions 2 and 3. | 0.69 / 0.97 |
| 6 | Optional block, only when the spend leaves room for it. | 1.56 / 1.13 |

```bash
cd ~/repos/chartula-evals

# Stage 0, once per plan
python3 tools/sweep.py sweeps/cmp-difficult-ingestor-v3.2.0.json --baseline

# A stage: the first repetition of one plan
python3 tools/sweep.py sweeps/cmp-difficult-ingestor-v3.2.0.json --dry-run --repetitions 1
python3 tools/sweep.py sweeps/cmp-difficult-ingestor-v3.2.0.json --repetitions 1

# One provider only: name its cells
python3 tools/sweep.py sweeps/cmp-difficult-ingestor-v3.2.0.json --repetitions 1 \
  --only openai-g-g--gpt-6-luna--gpt-6-luna \
  --only openai-g-m--gpt-6-luna--gpt-6.1-sol \
  --only openai-m-m--gpt-6.1-sol--gpt-6.1-sol

# After every stage: billed per provider, runs without a known cost, and what the runs still owed would cost
python3 tools/sweep_compare.py spend sweeps/prices-2026-10-09.json sweeps/cmp-*.json \
  --budget openai=5.50 --budget anthropic=5.50

# The optional block runs only when named
python3 tools/sweep.py sweeps/cmp-typical-servicedesklite-v1.9.0.json \
  --only openai-p-m--gpt-6-astra--gpt-6.1-sol
```

Leaving out `--repetitions` runs every repetition still owed; a finished run is skipped.

## What is kept and read

A run is `sweeps/<plan>/<cell>/run-<n>/`, for example `sweeps/cmp-typical-servicedesklite-v1.9.0/anthropic-g-m--claude-haiku-5-5--claude-sonnet-5-5/run-2/`.
It holds `changelog.json` with both texts, `CHANGELOG.md`, `release-<tag>.md`, the run record with the complete facts, the flags and the usage, `chartula.log`, and `sweep-run.json` with the settings asked for.

```bash
python3 tools/sweep_compare.py report sweeps/prices-2026-10-09.json sweeps/cmp-*.json
```

That writes `sweeps/cmp-2026-10-stats/`: per run and per cell, cost, tokens and duration for rendering and check apart, billed and uncached, retries, failed renderings, checks that could not be read, flags per audience, how often the same flag came back across a cell's repetitions, and the length and number of entries of each text.
A run without a record is listed with an unknown cost, and one with a call that reported no usage as a lower bound; neither is counted as zero.

## How it ran

| | Runs | Complete | Incomplete | Failed or mismatched | Billed, OpenAI | Billed, Anthropic |
| --- | --- | --- | --- | --- | --- | --- |
| Main matrix | 72 | 63 | 9 | 0 | 2.09 | 3.60 |
| Optional block | 12 | 11 | 1 | 0 | 0.82 | 0.87 |
| **All** | **84** | **74** | **10** | **0** | **2.91** | **4.47** |

Billed is what the run records give at the list prices of `prices-2026-10-09.json`, cache applied as it fell; it is not checked against an invoice.
The estimate above was 1.95 and 2.79 for the main matrix: the large case cost about one and a half times what it predicted, the other three were close.
No call was retried and none came back without usage.
Every run of a case read the same facts and the same release commits, on one version and one prompt.
The first three runs of the difficult case were marked `failed` and reclassified as `incomplete`, because they predate that status; each `sweep-run.json` says so.

## Limits on what the figures say

- A flag is what a checker reported, not a confirmed error.
- Fewer flags do not mean a better text.
- `g-g` and `g-m` each render anew, so they compare whole configurations. Nothing follows from them about the checking model alone.
- The models run at different thinking settings, each at its lowest.
- n = 3 per cell.
