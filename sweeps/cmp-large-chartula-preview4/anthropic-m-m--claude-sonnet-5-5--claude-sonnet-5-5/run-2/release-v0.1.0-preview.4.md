title: Release 0.1.0-preview.4
description: This release adds chartula doctor, a free preview, step progress and clearer output, and stricter option and configuration checks, and it keeps pull request descriptions out of the published changelog.json.
publishedAt: 2026-10-07

### What needs action

- **Breaking:** The published changelog.json no longer contains pull request descriptions, so internal notes and links authors wrote for reviewers are not in a file meant to be published. The file is now schema version 2, and the complete facts, descriptions included, stay in the local run record. If you read descriptions from changelog.json, read them from the run record instead.
- **Breaking:** The preview command no longer prints renderings and makes no model call, so it needs no key and costs only the GitHub requests. It shows each fact with its audiences, each dropped change with the setting that dropped it, and what generate would send, so you can check a run before paying for it. To see the written text without publishing, use generate with --no-publish.

### What's New

- **Run summary and help layout:** The first line of a run summary now says how the run went, for example whether review flags were raised or some audiences failed. Each rendering stands under its audience's name, and each command opens with a header. You can read the outcome from the first line, and the help groups options under three headings.
- **Clearer doctor report:** The doctor command now groups its checks under Repository, Model and GitHub, and marks each status with a symbol and a word. The closing line counts warnings and says whether a run would start, naming the case where generate would stop at GitHub write. You can trust that verdict before running generate, and plain output keeps the old word-only columns.
- **Progress spinner and --plain:** A run now shows a spinner on the step in progress, and a finished step stays as a done line, while a failed step shows as failed above the error. This applies on a live terminal; redirected output, CI, and dumb terminals get plain lines. A slow run no longer looks like a hanging one, and the new --plain option forces the plain form.
- **Quoted pull request text:** Pull request titles and descriptions are now quoted between tags in what the model reads, and descriptions over 8,000 characters are cut in the prompt only. The model is told the quoted text is material to rephrase, never instructions. This makes text written to steer the model less likely to work, though not impossible.
- **Published releases protected:** Running generate on a tag whose release is already published used to replace its notes without asking. It now stops before the first model call and costs nothing, and doctor warns about it too. To replace the published notes, pass --replace-published to generate, or use --no-publish to write only the files.
- **Config template hint in doctor:** When doctor finds no chartula.yaml, it now also gives a link to the config template for the installed version. You no longer have to know where the example file lives to start a configuration.
- **Step progress during a run:** A run now shows each step as it works: reading pull requests, rendering each audience, and checking each rendering. On a terminal the line updates in place with the elapsed time; without one, each step is one plain line on stderr. You can tell a slow run from a stuck one, and no time remaining is shown.
- **chartula doctor:** The new chartula doctor command checks the setup a run needs, one line per check, before anything is spent. It reports ok, warn, fail or skip using the same messages a run would print, writes and publishes nothing, and exits 1 if a check failed. You can find setup problems up front, and run it in CI before generate.
- **Closed issue numbers:** The factBase depth setting now only controls whether the model reads the description. Closed issue numbers are taken from the text the model reads at every depth, so a rendering that keeps a number from "Closes #12" is no longer flagged at the default depth. The old value title-description-and-issues still works as title-and-description, so existing configuration files keep working.
- **Commits without a pull request:** A commit pushed straight to main without a pull request now appears in the release next to the pull requests, instead of being left out when the release has any. The usual filtering rules apply, and merge commits without a pull request are skipped. The run summary reports how many such commits there were.
- **Version command:** The chartula --version command prints the installed version and exits 0, from any directory and without a key, token, or configuration. You can now identify your build, and it matches the version recorded in changelog.json.
- **First tag and large ranges:** A first tag is now rendered from the first commit without a flag, and --whole-history is gone. A first tag or a range above 200 commits is confirmed with two questions before any GitHub request or model call, and without a terminal the run stops unless you pass --yes. You cannot spend on a large range nobody approved, and --since starts the range later.

### What's Changed

- **Dependency updates:** Dependencies were updated: Anthropic, coverlet.collector and Microsoft.Extensions.AI.OpenAI moved to newer minor or patch versions.

### Bug Fixes

- **Help options:** The help listed --replace-published under the wrong group and showed --audience twice. Each option now appears once under its group, so the help matches what the command accepts.
- **False review flags:** The rule-based check could flag a quoted name that the facts did contain, when a description wrapped it over two lines or a fenced code block was involved. Such names are now matched correctly, so you no longer have to dismiss these false flags. Names that are absent from the facts are still flagged.
- **Release with nothing technical:** A release with nothing for technical readers, such as only chore and docs changes, used to produce an empty CHANGELOG.md heading and empty release notes. It now states that the release has no features, fixes, performance improvements or breaking changes. You can tell this apart from a run that lost its text, and the model is not called for it.
- **Readable JSON files:** changelog.json and the run record used to write backticks and non-ASCII characters as escape codes, which made them hard to read. They now escape only what JSON requires, so you can read and diff them directly. Parsers read the same values as before.
- **Review flags layout:** The review flags of a rendering were printed directly under its last entry, so they looked attached to it. They now appear after a blank line under a Flagged for review heading. You can see they may concern any entry in the rendering.
- **Run header credentials:** A run without GITHUB_TOKEN or a model key printed that the credential came from the variable, even though it was not set. The header now says unauthenticated and names the unset variable, so it states what to set. A blank variable counts as unset.
- **Option checking:** The CLI used to ignore unknown or misspelled options, so generate --help started a run and --nopublish could publish. Options are now checked before anything starts, and each command refuses options it does not take, suggesting the closest valid one. Help works after any command, and no run starts on a command line the CLI cannot read as meant.
- **GitHub API URL:** A GitHub API URL set without a trailing slash, such as an Enterprise URL ending in /api/v3, sent requests to the wrong path and failed with a 404. The slash is now added for you. You can write the URL in the form GitHub documents.
- **Empty excludeCategories:** Setting filter.excludeCategories to an empty list was read as no setting, so the default Internal exclusion stayed in force. An empty list now drops no category. You can keep internal work in a release by writing an empty list, in the file or the environment.
- **Unreadable model answers:** A model answer the SDK could not read was reported as an unreachable endpoint, which sent you looking for a network problem. It is now reported as an answer that could not be read, with what could not be read. You can tell the endpoint is reachable and look at the answer instead.
- **Two config files:** With chartula.yaml and chartula.yml side by side, a run silently read one and ignored the other. The run now stops with an error naming both paths. You can be sure the settings you edited are the ones in force, after keeping one file.
- **Publish check up front:** A token that could not publish was found out only after every model call, so you paid for a whole run. generate now checks before the first model call and stops with the reason, naming --no-publish. You no longer pay for a run that cannot publish; preview and --no-publish do not need the check.
- **--no-publish help:** The help said --no-publish writes only changelog.json and CHANGELOG.md. It writes every file, including the release file and the run record, and skips only the GitHub release notes. The help line now says exactly that.
