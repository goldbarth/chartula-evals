## 0.1.0-preview.4 - 2026-10-07

### Changed

- This release will bump the NuGet minor and patch dependencies: Anthropic from 12.49.0 to 12.53.0, coverlet.collector from 10.0.1 to 10.1.0, and Microsoft.Extensions.AI.OpenAI from 10.10.0 to 10.10.1. ([#328](https://github.com/goldbarth/chartula/pull/328))

### Added

- **Breaking:** This release will stop writing pull request descriptions into `changelog.json`, which becomes schema version 2 and carries no `description` on a change entry; the complete facts, descriptions included, move to a new `facts` array in the run record, and reading a fact base back comes from the run record, which refuses a record without facts. ([#294](https://github.com/goldbarth/chartula/pull/294))
- **Breaking:** This release will make `preview` run no model call and need no key: it shows the facts, the dropped changes with the setting that dropped each, and what `generate` would send (rephrasing calls per audience, prompt characters and the thorough check), and `generate --no-publish` replaces it for showing the prose. ([#292](https://github.com/goldbarth/chartula/pull/292))
- This release will open each run's summary with a first line stating how the run went, such as `Generated v1.3.0.`, `Partially generated v1.3.0: 1 of 3 audiences failed.` or `No audience rendered for v1.3.0.`, print each audience's name as a heading above its rendering, open stderr and stdout with the command's name, and group the help into Which release, What a run writes and How it looks. ([#342](https://github.com/goldbarth/chartula/pull/342))
- This release will group the `doctor` checks into Repository, Model and GitHub, mark each status with a symbol and a word, and state in its closing line whether a run would start, whether it would stop at GitHub write, or whether it would stop, with the exit codes unchanged. ([#341](https://github.com/goldbarth/chartula/pull/341))
- This release will show the run's progress with a spinner that fades along the brand colours where the terminal supports it, fall back to plain lines when output is redirected, in CI, under `TERM=dumb` or with `--plain`, and mark a failed step as failed rather than done. ([#340](https://github.com/goldbarth/chartula/pull/340))
- This release will quote pull request titles and descriptions between `<title>` and `<description>` tags in the model prompts, neutralise tags written inside the text, tell the model that the quoted text is material to rephrase and never instructions, and cut descriptions longer than 8,000 characters in the prompt only. ([#338](https://github.com/goldbarth/chartula/pull/338))
- This release will refuse `generate` before any model call when the tag's release is already published, unless `--replace-published` is given, and will check the same again before writing, so a published release's notes are not replaced silently. ([#335](https://github.com/goldbarth/chartula/pull/335))
- This release will name this version's `chartula.example.yaml` template, linked at its tag, when `doctor` finds no `chartula.yaml`. ([#329](https://github.com/goldbarth/chartula/pull/329))
- This release will show each step of a run while it works, reading pull requests, rendering each audience and checking each rendering, with a live count and time in a terminal and one plain line per step elsewhere. ([#297](https://github.com/goldbarth/chartula/pull/297))
- This release will add the `chartula doctor` command, which checks git, the checkout, the tag, the repository, the configuration, the model endpoint, GitHub read and write access and pull request titles before a run, prints one line per check and exits 1 when a check fails. ([#295](https://github.com/goldbarth/chartula/pull/295))
- This release will read closed issue numbers from the title and description the model reads at every `factBase.depth`, so `title-only` and `title-and-description` both fill `linkedIssues`, and will accept the old `title-description-and-issues`, `full` and `issues` values as `title-and-description`. ([#293](https://github.com/goldbarth/chartula/pull/293))
- This release will render a commit that belongs to no merged pull request as a change of its own and skip merge commits without a pull request, and the run will report the count of commits without one and of skipped merge commits. ([#291](https://github.com/goldbarth/chartula/pull/291))
- This release will print the installed version with `chartula --version`, in the form `chartula` followed by the informational version, exit 0 and need no checkout, configuration or key. ([#286](https://github.com/goldbarth/chartula/pull/286))
- This release will render a first tag from the first commit without a flag, and will ask for confirmation before reading a first tag's range or any range above `range.confirmAboveCommits` (default 200), with `--yes` to confirm up front; `--whole-history` is removed. ([#282](https://github.com/goldbarth/chartula/pull/282))

### Fixed

- This release will list each option of `chartula --help` once under its group and will document the flags in `docs/cli.md`, which also names a published release as a cause of a warning under GitHub write, with the ROADMAP updated to show the completed launch items. ([#344](https://github.com/goldbarth/chartula/pull/344))
- This release will make the rule-based faithfulness check compare names with whitespace folded and fenced code blocks removed, so a name wrapped over two lines in a description is no longer flagged, while a name the facts do not contain is still flagged. ([#336](https://github.com/goldbarth/chartula/pull/336))
- This release will write the sentence "This release has no features, fixes, performance improvements or breaking changes." into `CHANGELOG.md` and the release notes when the technical audience has nothing to report, while `changelog.json` keeps an empty technical rendering. ([#333](https://github.com/goldbarth/chartula/pull/333))
- This release will write `changelog.json` and the run record with only the escapes JSON requires, so backticks, quotes and non-ASCII characters read as themselves in the files. ([#332](https://github.com/goldbarth/chartula/pull/332))
- This release will set the flags of a rendering apart from its last entry, with a blank line, a `Flagged for review:` heading and each flag indented under it. ([#331](https://github.com/goldbarth/chartula/pull/331))
- This release will report an unset or blank `GITHUB_TOKEN` or model key as `unauthenticated` in the run header, naming the variable, instead of as a token or key taken from it. ([#330](https://github.com/goldbarth/chartula/pull/330))
- This release will check every command line before a run starts and refuse options a command does not take, values missing from value options, repeated single-value options and `--tag=...`, suggesting the closest option, while `-h` and `--help` print the help and exit 0 wherever they stand. ([#301](https://github.com/goldbarth/chartula/pull/301))
- This release will add the trailing slash to `Chartula__GitHub__ApiBaseUrl` when it is written without one, so requests reach the GitHub Enterprise API path rather than a path one segment up. ([#290](https://github.com/goldbarth/chartula/pull/290))
- This release will read an empty `filter.excludeCategories` list, in the file or in `Chartula__Filter__ExcludeCategories`, as dropping no category instead of keeping the default `[Internal]`. ([#289](https://github.com/goldbarth/chartula/pull/289))
- This release will report a model answer the SDK cannot read as unreadable, naming the answer's status and the value that could not be read, instead of as an endpoint that could not be reached. ([#288](https://github.com/goldbarth/chartula/pull/288))
- This release will refuse to run when both `chartula.yaml` and `chartula.yml` exist in the directory, naming both paths and how to keep one. ([#287](https://github.com/goldbarth/chartula/pull/287))
- This release will check before the first model call that the token may publish release notes, so a run whose token cannot publish stops with the permission GitHub requires instead of after every model call. ([#285](https://github.com/goldbarth/chartula/pull/285))
- This release will describe `--no-publish` as writing every file and publishing no GitHub release notes, in `chartula --help` and `docs/cli.md`. ([#284](https://github.com/goldbarth/chartula/pull/284))
