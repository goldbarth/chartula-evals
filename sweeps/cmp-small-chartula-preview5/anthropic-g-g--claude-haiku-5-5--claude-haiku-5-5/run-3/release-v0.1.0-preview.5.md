### What's New

- **Summary text in a terminal:** Release summaries in a terminal now read as formatted text instead of Markdown source: headings are bold without their hash marks, entries are bullets with a hanging indent, code is coloured without backticks, and links show as their text, such as (#294). The description appears above the entries as a plain sentence. Entries wrap at the width of the window, and a word longer than the room, such as a URL, is not cut. Breaking markers are teal and bold, and code is amber-glow. Redirected output, CI and --plain still print the Markdown and the description line as before, and docs/cli.md says where to copy the Markdown from.
- **Spinner and header alignment:** While a step runs, its spinner now sits right before its label, so the moving character is next to the text it belongs to. When the step ends, the done or fail mark takes the spinner's place, and the label, count and time stay where they were. The header values Model, GitHub and Range now start on the same column as the step labels, and their continuation lines are indented to match. Plain output is unchanged apart from the header values sitting one space further right.

### Bug Fixes

- **Failed audience step and skipped notes:** An audience that failed to render now ends its step as failed, so the step list no longer shows done directly above the failed audience. Publishing runs list the release notes under Skipped with the reason, either that the technical rendering failed or that --audience left it out. Without publishing, the notes appear under Skipped (--no-publish), including when the technical rendering failed. Plain output is unchanged.
- **Argument errors and messages:** A slip in --audience, such as a trailing comma or a number, is now refused with an error that names the three valid audiences. Every refused argument prints the same two lines, the error and a pointer to chartula --help, and the --repo value is checked before the run header is printed. Running chartula version now points to chartula --version. The Wrote list is followed by a blank line, the --plain help is clearer about NO_COLOR, and the rate limit message explains the 60 and 5000 request limits without a token and with GITHUB_TOKEN.
- **Numbers with thousands separators:** The rule-based faithfulness check now reads numbers written with thousands separators as one number, so 8,000 in the facts matches 8000 in a rendering and the reverse. A comma is treated as a separator only when exactly three digits follow it, so lists such as 1, 2, 3 are still separate numbers. Three-digit numbers written without a space, such as 100,200, are read as one number. Flagged numbers are quoted as the rendering wrote them.
- **Running step line and doctor details:** A running step's line is fitted to the terminal's width and redrawn as the window changes, so it no longer wraps and leaves rows behind in a narrow window. When space runs short, parts drop in order: the padding and the word commits, then the time, then the count, then the end of the label. On terminals narrower than ten columns no frame is drawn and the step shows its finished line once. In chartula doctor, details longer than the window break between words with the indent kept on each row on a terminal. Plain output is not broken.
